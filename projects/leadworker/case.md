# Leadworker MTProto — адресация и обработка отправки

**Статус: READY (локальный пакет).** Приватный исходник; пакет локальный.

Небольшой внутренний backend, принимающий сообщение через API и выбирающий способ адресации Telegram-получателя. Показывает интеграционную разработку: валидацию, авторизацию, разрешение username, резервный InputPeer, таймаут и нормализацию ошибок.

## ORIGINAL

Источник `LeadworkerMTProto`, commit `beac7c0a30789998b4f09fc204a6347e4f78744d`. Изучены src/server, env schema, routes/sendMessage, client/baseClient, Vercel endpoints и OpenAPI. TypeScript, Node HTTP, GramJS/Telegram, Vercel handler. В исходнике нет CRM, AI-квалификации, поиска лидов или frontend-продукта — эти возможности не приписываются сервису.

## VERIFIED

Исходные `api/send-message.ts` и `src/routes/sendMessage.ts` транспилированы и выполняются в изолированной среде. Реальные env и Telegram client не загружаются. Проверены восемь API сценариев: username→200, fallback InputPeer→200, no hints→400, empty message→400, missing entity→400, timeout→504, unauthorized→401, wrong method→405. Ошибки авторизации/метода останавливаются до транспорта. Дополнительно 18 UI прогонов (6 сценариев×390/768/1440), без page errors и overflow.

## DEMO / MOCK

Mock GramJS classes/client, вымышленный адресат и сообщение, локальный открытый demo-токен. Ответы транспорта подготовлены для success/failure/timeout; отправок нет, session strings и личные аккаунты не используются. Отображаемая длительность — замер локального стенда, не производительность Telegram и не SLA.

## Ограничения

Облачное развёртывание и настоящая доставка не проверены. Таймаут Promise.race не отменяет продолжающийся транспортный вызов — серверный timeout нельзя считать гарантией неотправки. In-memory delay не является распределённым rate limiter. Отдельный локальный src/server.ts не передаёт username/accessHash в sender; демо использует более полный Vercel handler. Поток входящих запросов стенда предназначен для последовательной локальной демонстрации, не production.
