# AI Support — ответ с опорой на знания

**Статус: READY (локальный пакет).** Локальный пакет. Клиентские данные и разрешение на публикацию не подразумеваются.

Система помогает оператору подготовить ответ: сначала ищет готовый FAQ, затем подбирает фрагменты базы знаний и формирует черновик. Оператор проверяет текст перед отправкой. Исходная коммуникация организована через Telegram, а веб-чат этого же проекта представлен отдельным кейсом Webchat.

## ORIGINAL

Источник: предоставленная папка `РАБОТА/Сервисы/tg-business-rag-worker (2)`, целый экспорт `backend-webchat-clean/src`. Сопоставление со старым кейсом подтверждается конкретной архитектурой: Cloudflare Worker, D1, R2, Telegram topics, operator drafts, React webchat и widget. Старые цифры 95%, 5× и uptime не подтверждены и в кейс не перенесены.

Изучены worker routes, ask, webhook callbacks, storage, QA matcher, RAG search, prompts, LLM parser, language detection, schema/migrations и фронтендная документация. Стек: TypeScript, Workers bindings, D1 SQL, R2, Telegram API. В исходнике есть сохранение двуязычных черновиков, редактирование, sent/cancelled, блокировки, вложения, рейтинги и обучение по ответам оператора.

## VERIFIED

Запущен исходный handleAsk → matchQa / searchRag → buildPrompt → generateDraft. AutoRAG/AI bindings заменены подготовленными ответами. Исходный StorageClient выполняет SQL через локальный SQLite/D1 adapter. Проверены 12 API-сценариев, включая FAQ без вызова модели, фильтрацию слабого источника, сохранение/правку/локальное подтверждение, пустые источники, malformed model response, сбой провайдера и валидацию HTTP. UI: 390/768/1440, 9 сценариев на каждом размере. См. api-qa.json и ui-qa.json.

## PORTFOLIO POLISH

Новая тёмная техническая панель показывает существующую backend-логику. Это не исходный интерфейс Telegram и не ранее выпущенный SaaS. Панель включает демо-очередь, обращение, редактор, источники и историю. При ошибке модели локальная копия сохраняет русский язык fallback вместо исходного английского ответа. Подтверждение/отмена вызывают методы StorageClient, но не весь Telegram webhook; защита от повторного подтверждения реализована в адаптере стенда.

В верхнем `src` найден незавершённый файл storage и отсутствующие константы. Для демо использован целый экспорт `backend-webchat-clean` из того же архива: ручное восстановление этих частей не включено в финальную версию. Обе source manifest сохранены, чтобы происхождение было проверяемым.

## Границы проверки / PLANNED

Живые Telegram topic creation, доставка, R2 sync, рейтинги, медиавложения, внешняя модель и индекс не прогонялись. Эти ветки подтверждены чтением исходников, но не обозначены как VERIFIED. Локальная БД в памяти очищается при перезапуске; рабочая D1 не подключалась. Нельзя делать вывод «без галлюцинаций» из подготовленного ответа. Исходный searchRag возвращает слабые совпадения, если сильных нет; это ограничение не маскируется заявлением о гарантированной точности. Две системы определения языка имеют разные эвристики. Подтверждение личной роли и прав показа остаётся в QUESTIONS.md.

## SCREEN → ACTION → STATE → RESULT

Очередь → выбрать обращение → новый вопрос → запрос готов.
Обращение → подготовить → loading → FAQ или RAG-черновик.
Источники → прочитать основание → найденные/пустые → оператор проверяет текст.
Редактор → правка → сохранённый draft → локальное подтверждение/отмена.
История → открыть → сохранённый текст → завершённый ответ read-only.
Провайдер → сбой/невалидный JSON → fallback → оператор решает дальнейшие действия.

## Дизайн-ориентиры

Использован skill frontend-design-direction. Рабочая задача — быстро сопоставить вопрос, ответ и основание; графитовые поверхности, компактная типографика, один спокойный акцент, минимум оболочек. Структурные ориентиры, без копирования фирменных материалов: [Intercom Inbox](https://www.intercom.com/helpdesk/inbox) — соседство разговора и контекста; [Front quickstart](https://help.front.com/en/articles/2194) — очередь обращений; [Zendesk auto assist](https://support.zendesk.com/hc/en-us/articles/8984493142810-Setting-up-auto-assist) — операторская проверка предложенного ответа. Эти продукты не являются источниками кода проекта.

## REAL TELEGRAM EVIDENCE

21 сентября пользователь передал настоящий экран операторской поддержки и подтвердил, что он относится к этому проекту. Текст поддержки, кнопки, структура Telegram и временные метки сохранены. Исходный screenshot находится только в рабочей исследовательской папке и не копируется в публичный репозиторий.
